# 产品需求文档（PRD）

## 已确认需求

### `/protected` 生图入口页

#### 页面定位与视觉参考

- 将 `/protected` 页面设计为生图需求的主要入口页。
- 页面布局和视觉呈现参考 `/docs/images/protected.png`。
- 页面主体包含生图提示词输入区域，输入区域下方展示“最近项目”区域。

#### 生图提示词输入

- 页面提供提示词输入框，用户可以输入生图需求描述。
- 输入框内包含“+”按钮。
- 点击“+”按钮后，用户可以从本地选择并上传图片。
- 输入框内提供发送操作入口。

#### 发送与页面跳转

- 提示词为必填项，参考图为可选项；提示词为空时发送按钮不可用。
- 用户首次从 `/protected` 发送时，系统先创建一个归属于当前用户的新项目，再使用该项目 ID 跳转并提交生成任务。
- 新项目初始名称为 `Untitled`，首次请求提交后可使用提示词生成便于识别的项目标题。
- 用户点击发送后，进入对应的项目画布页面。
- 目标路由格式为：`/canvas?projectId={projectId}`。
- `/canvas` 页面的已确认功能和交互需求见“`/canvas` 项目画布页”。

#### 最近项目

- 提示词输入区域下方按更新时间倒序展示最近 4 个项目。
- 项目卡片展示封面、项目名称和更新时间；点击卡片进入 `/canvas?projectId={projectId}`。
- 最近项目区域提供查看全部项目的入口。
- 点击查看全部项目的入口后，跳转到 `/projects` 页面。
- `/projects` 页面用于查看全部项目。

### `/projects` 全部项目页

#### 页面定位与视觉参考

- `/projects` 页面用于加载和展示当前用户的全部项目。
- 页面布局和视觉呈现参考 `/docs/images/projects.png`。
- 项目以多列卡片网格形式展示。
- 项目卡片展示项目封面、项目名称和更新时间。
- 项目默认按更新时间倒序加载，每批加载 24 个，并在用户滚动到底部时继续加载。
- 页面需要提供加载中、空数据、加载失败和重试状态。
- 首版支持项目重命名和删除，不提供搜索及复杂筛选。
- “新建项目”卡片会创建一个空项目，并进入对应的 `/canvas?projectId={projectId}` 页面。

#### 项目访问

- 用户点击任意已有项目卡片后，进入该项目对应的画布页面。
- 目标路由格式为：`/canvas?projectId={projectId}`，其中 `projectId` 为被点击项目的 ID。

### `/canvas` 项目画布页

#### 页面定位与空状态

- 页面路由格式为 `/canvas?projectId={projectId}`，通过 `projectId` 标识当前项目。
- 项目不存在、已删除或当前用户无权访问时统一显示 404 页面。
- 页面空状态的布局和视觉呈现参考 `/docs/images/canvas-empty.png`。
- 页面采用左右分栏布局：左侧为项目画布，右侧为图片生成对话面板。

#### 左侧画布

- 左侧画布使用 `@xyflow/react` 实现。
- 产品采用自由图片白板模式，画布用于承载当前项目的图片素材和后续生成结果，不作为节点连线式工作流编辑器使用。
- 首版画布支持图片节点的选择、多选、拖动、缩放、复制、删除、调整层级，以及画布的缩放、平移和适应视图。
- 画布节点、层级和视口由整个项目共享，并在变更停止约 `800ms` 后自动保存；对话消息和生成任务状态在产生时立即持久化。
- 项目尚无画布内容时，显示参考图中的空状态引导。

#### 右侧生成对话面板

- 右侧区域为图片生成对话面板。
- 每个项目允许创建多个独立对话，所有对话共享该项目的同一份画布。
- 切换对话只切换右侧对话记录，不切换或清空左侧项目画布。
- 用户可以拖动左右分栏之间的边界，调整对话面板宽度。
- 对话面板最小宽度为 `320px`，最大宽度为 `620px`。
- 对话面板默认宽度为 `384px`，用户调整后的宽度保存在本地浏览器中。
- 调整宽度时，左侧画布占用其余可用空间。

#### 生图模型与图标

- 页面支持 `Nano Banana2` 和 `GPT Image2` 两种生图模型。
- 默认生图模型为 `GPT Image2`。
- 模型相关入口需要显示对应品牌图标。
- `GPT Image2` 使用 `@lobehub/icons` 提供的 OpenAI Icon。
- `Nano Banana2` 使用 `@lobehub/icons` 提供的 NanoBanana Icon。

#### 模型配置通用交互

- 生图输入区域提供配置按钮和当前配置文案。
- 点击配置按钮后，在按钮附近显示当前模型对应的配置弹框卡片。
- 用户修改配置后，输入区域中的配置文案需要同步变化，以反映当前生效的模型参数。
- 配置选项点击后即时生效，无需额外确认按钮。
- 每个模型分别保留自己的最近一次配置，切换模型时恢复该模型的配置。
- 两种模型显示各自独立的配置项和弹框内容。

#### Nano Banana2 配置

- 配置弹框的布局和视觉呈现参考 `/docs/images/canvas-nanobanana-config.png`。
- 配置项以 Kie AI Nano Banana2 API 文档为准，不提供 API 未支持的 `512` 分辨率。
- 支持选择分辨率：`1K`、`2K`、`4K`，默认 `1K`。
- 支持选择画面比例：自动、`1:1`、`2:3`、`3:2`、`1:4`、`4:1`、`3:4`、`4:3`、`4:5`、`5:4`、`1:8`、`8:1`、`9:16`、`16:9`、`21:9`，默认自动。
- 支持选择输出格式：`JPG`、`PNG`，默认 `JPG`。
- 用户完成选择后，配置文案需要展示当前分辨率、画面比例和输出格式。

#### GPT Image2 配置

- 配置弹框的视觉风格参考 `/docs/images/canvas-gptimage2-config.png`，配置内容以 Kie AI GPT Image2 API 文档为准。
- 不提供 API 未支持的质量、自定义宽高和单次生成数量配置；每次任务生成一组 API 返回的结果。
- 支持选择分辨率：`1K`、`2K`、`4K`，默认 `1K`。
- 支持选择画面比例：自动、`1:1`、`3:2`、`2:3`、`4:3`、`3:4`、`5:4`、`4:5`、`16:9`、`9:16`、`2:1`、`1:2`、`3:1`、`1:3`、`21:9`、`9:21`，默认自动。
- `2K` 不支持 `5:4`、`4:5`、`3:1`、`1:3`、`9:21`。
- `4K` 不支持 `1:1`、`3:1`、`1:3`、`9:21`。
- 选择自动画面比例时仅允许 `1K`；选择不兼容组合时，界面需要禁用对应选项或自动回退到可用组合。
- 支持选择背景：自动、透明、不透明，默认自动；背景参数仅在 `1K` 时显示并提交。
- 用户完成选择后，配置文案需要展示当前分辨率、画面比例和适用的背景设置。

#### 参考图选择

- 生图输入区域提供“参考图”入口。
- 点击“参考图”后显示来源选择菜单，布局和视觉呈现参考 `/docs/images/canvas-upload.png`。
- 来源选择菜单提供“从本地上传图片”和“从画布选择”两个选项。
- 选择“从本地上传图片”后，允许用户从本地选择图片，并将图片上传到 Supabase Storage Bucket。
- 本地图片上传成功后，使用 Storage 中对应的远程图片地址作为参考图地址。
- 选择“从画布选择”后，允许用户从当前项目画布的图片中选择一张作为参考图。
- 选择“从画布选择”后进入画布图片选择模式，用户点击一个图片节点完成选择，并可通过取消操作或 `Esc` 退出选择模式。
- 从画布选择图片时，直接复用该画布图片已有的远程地址，不重复上传图片。
- 单次生图请求最多只能使用一张参考图。
- 本地参考图仅接受 JPEG、PNG 和 WebP，单文件最大 `10MB`。
- 本地上传使用私有 Supabase Storage Bucket `project-assets`，对象路径格式为 `{userId}/{projectId}/{assetId}.{ext}`。
- 数据库保存 Bucket 和对象路径，不持久化有有效期的签名 URL。
- 删除项目或资源时先更新数据库状态，再异步清理对应 Storage 对象，避免文件删除失败导致业务事务中断。

#### 参考图已选择状态

- 参考图选择或上传完成后的输入区域样式参考 `/docs/images/canvas-uploaded.png`。
- 已选择的参考图以缩略图形式显示在输入区域中。
- 输入区域同时保留提示词、模型配置和发送入口。
- 当已经存在一张参考图时，不允许继续添加第二张参考图。
- 用户可以删除已选参考图；重新选择图片时替换当前参考图。
- 本地上传需要显示上传中状态；上传失败时保留输入内容并提供重试入口。

#### 生成中状态

- 用户点击发送后进入生成中状态，布局和视觉呈现参考 `/docs/images/canvas-loading.png`。
- 对话面板追加本次用户请求，展示参考图缩略图、提示词、所选模型和当前配置摘要。
- 对话面板中显示生成结果占位区域。
- 左侧画布同步创建生成结果占位节点，并显示明确的生成中状态。
- 生成未完成前，占位内容应保持与本次请求关联。
- 供应商没有提供可用的精确进度时，使用不确定进度的 Loading 状态，不展示虚假的百分比。
- 当前 API 未提供取消任务接口，首版不支持取消已提交的生成任务。

#### 生成完成状态

- 图片生成完成后的布局和视觉呈现参考 `/docs/images/canvas-done.png`。
- 对话面板中的生成占位区域替换为最终生成图片。
- 左侧画布中的生成占位节点同步替换为最终生成图片。
- 生成结果作为当前项目画布内容保留，并与对应的对话请求保持关联。
- 每个生成结果提供“下载”“重新生成”“设为参考图”和“删除”操作。
- “设为参考图”会将该生成结果设置为当前输入区域的唯一参考图。
- “删除”需要移除对应的生成结果展示；底层文件清理遵循项目资源清理规则。
- 生成失败或超时时，对话面板保留原请求和失败状态，并提供重新生成入口。

#### 费用与额度

- 首版不接入支付、订阅、积分或用户额度体系。
- 即使首版不收费，服务端仍需对生成接口实施基础频率限制，避免接口被滥用或产生失控成本。

#### 生图服务接入

- GPT Image2 与 Nano Banana2 均通过 Kie AI 服务端 API 接入，生产 API 地址为 `https://api.kie.ai`。
- 所有 Kie AI 请求必须由应用服务端发起，并使用 Bearer API Key 鉴权；API Key 不得发送到浏览器。
- 创建任务统一调用 `POST /api/v1/jobs/createTask`，成功后保存返回的 `taskId`。
- GPT Image2 在没有参考图时使用模型 `gpt-image-2-text-to-image`，存在参考图时使用 `gpt-image-2-image-to-image`。
- Nano Banana2 使用模型 `nano-banana-2`，参考图通过 `image_input` 传入。
- 生成任务采用异步轮询模式，首版不传 `callBackUrl`，不接入 Webhook。
- 应用服务端使用 `GET /api/v1/jobs/recordInfo?taskId={taskId}` 查询任务状态，浏览器只轮询应用自己的任务状态接口，不直接访问 Kie AI。
- 任务处于 `waiting`、`queuing` 或 `generating` 时继续轮询；`success` 和 `fail` 为终态。
- 单个活跃任务从约 3 秒轮询间隔开始，逐步退避到约 5 秒；最长等待 15 分钟，超时后停止自动轮询并允许用户手动重试查询。
- 任务查询返回的供应商图片地址只作为临时结果；应用需要尽快将最终图片转存到 Supabase Storage 后再持久化。
- 用户提示词最大长度为 `20,000` 个字符。
- Kie AI 返回 `401` 或 `402` 时提示服务配置或余额异常且不自动重试；`422` 提示请求参数无效；`429`、`455`、`500` 和 `501` 允许用户稍后重新生成。

### Pi Agent 创作模式

#### 统一输入框与模式切换

- `/canvas` 右侧继续使用现有消息区和输入框，不新增独立 Agent 页面或左侧面板。
- 输入框内部底部工具栏最左侧提供“Agent / 生图”模式下拉框，并位于模型选择入口之前；按钮显示当前模式名称和向下箭头，菜单向上展开。
- 模式菜单提供“Agent”和“生图”两个选项，支持键盘选择、`Esc` 关闭和点击外部关闭。
- 生成任务执行或附件上传期间禁止切换模式。
- Agent 模式仅显示“Agent自动规划”，隐藏模型、比例和分辨率配置。
- 生图模式在模式下拉框右侧保留原有模型与参数配置，并完全保留既有普通生图链路。
- 窄屏时底部工具栏允许配置项换行，但发送按钮必须始终保留在输入框内且可操作。

#### 统一附件

- 输入框提供统一“附件”入口，支持 JPEG、PNG、WebP 图片和 Markdown 文件。
- 除文件选择器外，支持把文件拖入输入框，以及直接复制、粘贴文件。
- 所有附件存放在现有 Supabase 私有 `project-assets` Bucket，并校验当前用户和项目归属。
- 图片附件显示缩略图；Markdown 显示宽度不超过 `240px` 的紧凑附件卡片，长文件名省略。
- 点击附件可进行安全预览或下载；Markdown 原文由服务端读取并交给 Agent，不在浏览器执行 HTML 或危险链接。
- 发送后立即清空未发送的文字、图片、Markdown 附件、所选 Skill 和上传提示；已发送消息必须继续显示当次附件和技能名称。下一条消息不默认选中技能。

#### Agent Skill

- Agent 输入框在「附件」旁提供「Skill」入口。
- 用户可以上传标准 `SKILL.md`：YAML frontmatter 必须包含 `name` 与 `description`，正文保存完整规则。
- 技能按当前用户和当前项目隔离保存与校验；`name` 只能使用小写字母、数字和连字符，不允许路径穿越。
- Skill 列表展示名称和简介；简介默认最多两行，超出省略。
- 用户可以移除自己的技能。
- 发送时把本次技能名称写入用户消息并和图片、文件附件、文字一起显示在靠右的紧凑消息中。
- `docs/skills/` 下的技能是内置技能：每个项目的 Skill 列表默认可见并可直接选用，无需上传。列表中标记「内置」，不提供删除入口；上传同名 `SKILL.md` 会以项目自己的版本覆盖内置版本，删除该上传后内置版本恢复。
- 内置技能以 `docs/skills/<name>/SKILL.md` 为唯一来源，目录名必须与 frontmatter 的 `name` 一致，标识为 `builtin:<name>`，不写入数据库。
- 内置技能包含 `wechat-cover`：读取 Markdown 全文、提炼主题与短标题，先询问「极简大字报 / 杂志封面 / 插画 / 科技 / 孟菲斯」，用户选择后在同一轮用现有 GPT Image 2.5 Flare 工具生成 4 张同风格、不同构图的宽幅公众号封面，不新建生图链路。

#### 画布素材与有序引用

- Agent 模式下点击画布图片会按点击顺序加入输入框，显示为有序参考图。
- Agent 需要理解“图一、图二”等自然语言素材指代，并必须先通过工具实际查看对应图片，再发起相关生图任务。
- 上传的图片会同步成为画布节点，支持拖动、复制粘贴、等比缩放，以及选中后用 `Delete` 或 `Backspace` 删除节点。
- 图片节点的选择范围必须贴合素材实际宽高，不得因为固定节点尺寸在竖图两侧留下大块白边。
- 当焦点位于输入框、Markdown 编辑区域或其他可编辑文本区域时，删除键不得删除画布节点。
- 刷新页面后必须保留画布节点和节点删除结果；删除画布节点只移除画布展示，不删除底层素材文件。

#### Agent 回复与运行过程

- Agent 的回复、思考过程和工具调用过程通过右侧原有消息区实时流式显示。
- Agent 回复支持安全 Markdown 渲染，包括粗体、列表、分隔线、表格和代码块；禁止执行原始 HTML 和危险链接。
- 每次工具调用显示为可展开卡片，可查看工具名称、参数、结果和错误。
- 用户发送的文字与附件组成靠右、紧凑的用户消息，附件顺序与提交时一致。
- Agent 运行、消息、思考增量和工具调用事件必须真实持久化，不使用伪造响应替代 Pi Agent 或工具执行结果。

#### Agent 能力与工具

- Agent 使用 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`，并以实际安装包类型和 README 为实现依据。
- Agent 推理模型使用 DeepSeek；服务端从 `DEEPSEEK_API_KEY` 读取密钥，默认请求 `https://api.deepseek.com`，模型名为 `deepseek-flash`。密钥不得发送到浏览器。
- DeepSeek 接入参数以官方文档为准：OpenAI 兼容地址为 `https://api.deepseek.com`，当前官方模型名为 `deepseek-flash` 与 `deepseek-v4-pro`。Agent 默认使用带原生视觉能力的 `deepseek-flash`。旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 已下线，不得作为默认配置。
- Agent 至少提供以下真实工具：列出当前项目素材、查看指定图片、生成图片、将已有素材放到画布、读取当前画布。
- 每个工具调用都必须校验当前用户、项目、对话、素材及画布的归属关系。

#### Agent 生图

- Agent 生图统一使用 KIE GPT Image 2.5 Flare，不沿用普通生图模式中的旧 GPT Image2 模型。
- 无参考图时使用 `gpt-image-2-5-flare-text-to-image`；存在参考图时使用 `gpt-image-2-5-flare-image-to-image`，参考图通过 `input_urls` 提交。
- 具体请求字段、参数和结果结构以 KIE 官方 GPT Image 2.5 文档为准，不根据旧模型字段猜测。
- Agent 必须完整保存实际使用的有序参考素材、模型名称与生成参数。
- 生成结果进入既有生成任务记录、素材库、消息区和项目画布。
- Agent 任务的重试或重新生成继续使用 GPT Image 2.5 Flare，不得回退到 GPT Image2 或其他旧模型。

## 产品决策记录

- `/protected` 作为生图需求入口页，并采用“提示词输入 + 图片上传 + 最近项目”的页面结构。
- 创建或进入项目画布时使用 `/canvas?projectId={projectId}` 路由格式。
- 全部项目统一通过 `/projects` 页面查看。
- `/projects` 使用项目卡片网格展示全部项目，点击已有项目卡片后进入对应画布。
- `/canvas` 使用 `@xyflow/react` 实现左侧画布，并在右侧提供宽度可调的图片生成对话面板。
- `/canvas` 是自由图片白板，不使用节点连线式工作流；每个项目允许多个对话，所有对话共享同一画布。
- `/canvas` 支持 Nano Banana2 与 GPT Image2 两种生图模型，默认使用 GPT Image2，并为不同模型提供独立配置弹框。
- 两种模型的配置界面以 Kie AI API 文档为准，不展示供应商接口不支持的参数选项。
- 模型配置修改后，输入区域中的配置文案必须同步反映当前参数。
- `/canvas` 的单次生图请求最多使用一张参考图；本地图片上传到 Supabase Storage，画布图片直接复用已有远程地址。
- 生图请求提交后，画布与对话面板同步展示生成中占位，并在完成后同步替换为最终生成结果。
- 首版不接入支付或用户额度体系；生成结果支持下载、重新生成、设为参考图和删除。
- `/canvas` 在同一输入框中提供 Agent 与普通生图两种模式；Agent 使用 Pi Agent + DeepSeek（`deepseek-flash`）规划，并通过真实工具读取素材、理解画布和调用 KIE GPT Image 2.5 Flare。
- 图片和 Markdown 使用统一附件入口；图片可作为有序画布引用，Markdown 由服务端安全读取供 Agent 使用。
- Agent 对话框提供 Skill 入口：上传标准 SKILL.md、按用户与项目隔离保存、发送时记录本次技能名称；`docs/skills/` 下的技能作为内置技能默认出现在每个项目中，wechat-cover 封面技能开箱可用。
- Agent 的文本、思考和工具事件在原有消息区实时流式呈现并持久化。
